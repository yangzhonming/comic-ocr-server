# 漫画阅读页识别与首图定位插件

这是独立的 Chrome/Edge Manifest V3 插件。当前完成长漫阅读页判定、黑白名单纠错、阅读容器与首图定位、视口固定悬浮球、逐图编号，以及前端切片和绝对坐标索引。

## 安装与操作

1. 在 `chrome://extensions` 或 `edge://extensions` 开启开发者模式。
2. 选择“加载已解压的扩展程序”，加载整个 `newplugin` 文件夹。
3. 双击 `newplugin/start_capture_server.bat` 启动本地图片接收服务，保持终端窗口运行。
4. 刷新漫画章节页。悬浮球定位成功后，滚动浏览可见图片左上角的红色序号，用于检查页序。
5. 点击悬浮球，选择“开始切片并上传”。前端先确认图片尺寸、锁定坐标系，再提取局部像素寻找切线。接收器保存 `coordinates.json`、`slices.json` 和 `slice_序号_起点Y_终点Y.jpg`；原图不再上传。网页上的蓝色虚线显示原图绝对起点，上传成功的切片用绿色切线标出序号和绝对像素高度。
6. 点击扩展图标，在 Popup 中查看页面状态；误判可加入黑名单，漏判可加入豁免名单。

本地示例：运行 `node frontend_v2_demo/demo-server.js`，打开 `http://127.0.0.1:8766/reader.html`；图集负例为 `http://127.0.0.1:8766/gallery.html`。

阶段一的名单与识别交接见 [HANDOFF.md](HANDOFF.md)；首图定位和悬浮球见 [PHASE2_LOCATION.md](PHASE2_LOCATION.md)；旧版逐图采集记录见 [PHASE3_CAPTURE.md](PHASE3_CAPTURE.md)；当前切片流程见 [PHASE4_SLICE.md](PHASE4_SLICE.md)。

## 判定与名单

- 自动判定寻找占主导的纵向连续大图区域，检查宽度、图片间文字、多个竞争区域、图库网格和章节线索。URL 关键词只加分，不直接放行。
- 没有足够图片时保持等待；后续图片加载会重新评估。当前规则针对普通 `img` 长漫，CSS 背景图、Canvas、封闭 Shadow DOM 等暂不识别。
- 名单使用 `chrome.storage.local` 持久化，以主机名为基础；若 URL 存在 `/manga`、`/webtoon` 等栏目，则按“主机名 + 栏目”保存。黑名单优先于任何豁免规则。首页、目录和作品封面页的误判只禁用该路径，避免把真正的章节一起封锁。以前保存的完整 URL 和章节规则仍可读取和移除。
- 先运行自动判定；自动证据不足时，豁免名单作为保底。明确的章节 URL 需有基本大图证据；`/manga/作品名` 等没有章节号的栏目子路径需有更强的连续大图证据。网格、图文页和栏目首页不会仅因豁免而出现悬浮球。
- 识别器返回网页侧 DOM 锚点，协调器只向 Popup 发送可序列化状态；同容器内更靠上的懒加载占位首图也可用于定位。悬浮球位于 Shadow DOM 的 `position: fixed` 视口层，不跟随漫画图片滚动。
- 图片编号按阅读区图片顺序确定；只渲染视口内的序号徽标。切片坐标以本次章节的 `coordinateId` 和统一宽度为基准，服务端按 `slice_index` 和绝对 Y 保存切片。

这是启发式识别版本，不能仅靠页面布局保证区分所有图片博客与漫画页。黑白名单用于用户纠错；正式准确率需要用真实正反例页面验证。
